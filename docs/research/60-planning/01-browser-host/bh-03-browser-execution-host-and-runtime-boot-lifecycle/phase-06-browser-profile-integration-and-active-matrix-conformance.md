# Phase 6 - Browser Profile Integration and Active-Matrix Conformance

Back to milestone: [README](README.md)

- [x] 6 Phase - Browser Profile Integration and Active-Matrix Conformance.

  Compose the reusable BH-03 startup, shared-runtime, independent-root,
  shutdown, recovery, and fallback boundaries in the Phoenix development
  profile. Execute the same governed integration scenarios in the active Linux
  Chrome and Firefox matrix without promoting either browser to supported.

  - [x] 6.1 Section - Authorize Phase 6 and freeze the profile contract.

    - [x] 6.1.1 Task - Bind authority and predecessor truth.

      - [x] 6.1.1.1 Subtask - Record synchronized `main`, exact base, working branch, four-section delivery, one PR, merge, synchronized-main return, and local/remote branch deletion.
      - [x] 6.1.1.2 Subtask - Bind Phase 5 completion, contract, integration index, implementation evidence, and the BH-03 lifecycle vocabulary by SHA-256.
      - [x] 6.1.1.3 Subtask - Exclude Phase 7 measurements, BH-03 acceptance, renderer interaction transport, server commands, product components, publication, support, and public stability.

    - [x] 6.1.2 Task - Freeze profile and active-matrix behavior.

      - [x] 6.1.2.1 Subtask - Add a separate `/bh03/` profile that preserves `/bh01/` and serves only a governed, same-origin inventory.
      - [x] 6.1.2.2 Subtask - Require exact manifest negotiation, verified artifact startup, one shared runtime, two independent roots, intentional fallback, and deterministic shutdown.
      - [x] 6.1.2.3 Subtask - Require Chrome and Firefox to execute the same scenario set; any unavailable or failed active row blocks Phase 6 rather than becoming a false pass.

  - [x] 6.2 Section - Compose the reusable lifecycle in the Phoenix profile.

    - [x] 6.2.1 Task - Build and serve a governed BH-03 profile.

      - [x] 6.2.1.1 Subtask - Produce a deterministic `/bh03/` asset inventory from exact runtime artifacts and reusable JavaScript modules.
      - [x] 6.2.1.2 Subtask - Serve `/bh03/` with the existing isolation, content-type, cache, range, and ETag rules without changing `/bh01/` artifacts.
      - [x] 6.2.1.3 Subtask - Verify that manifest identities, artifact bytes, and the complete profile inventory fail closed on drift.

    - [x] 6.2.2 Task - Exercise shared runtime and independent roots through the profile.

      - [x] 6.2.2.1 Subtask - Start one verified runtime scope and coalesce concurrent compatible opens.
      - [x] 6.2.2.2 Subtask - Register, mount, update, move, dispose, and remount two independent roots through the retained runtime transport.
      - [x] 6.2.2.3 Subtask - Expose bounded profile snapshots and user-invokable restart/stop controls without declaring a stable API.

  - [x] 6.3 Section - Execute the active Chrome and Firefox matrix.

    - [x] 6.3.1 Task - Add one browser-independent scenario runner.

      - [x] 6.3.1.1 Subtask - Drive exact-match startup, runtime sharing, two-root lifecycle isolation, fallback, and shutdown scenarios from one runner.
      - [x] 6.3.1.2 Subtask - Record exact executable, browser version, host environment, scenario result, and bounded diagnostics for each active row.
      - [x] 6.3.1.3 Subtask - Reject absent rows, divergent scenario sets, profile drift, or browser failures.

    - [x] 6.3.2 Task - Retain honest active-matrix evidence.

      - [x] 6.3.2.1 Subtask - Execute Linux Chrome and Firefox against the Phoenix-served `/bh03/` profile.
      - [x] 6.3.2.2 Subtask - Record unavailable Safari, mobile, device, second-host, and manual assistive-technology rows as deferred under policy, never passed.
      - [x] 6.3.2.3 Subtask - Keep all browser support states unsupported and carry observations, not release budgets, into Phase 7.

  - [x] 6.4 Section - Run the inherited gate and publish completion evidence.

    - [x] 6.4.1 Task - Execute the active Phase 6 checks.

      - [x] 6.4.1.1 Subtask - Run project-local Mix/Node tests and builds, profile verification, active browser scenarios, Phase 1 through Phase 6 validators/tests, inherited validators/generators, JSON, archive, tracked-file, and patch hygiene.
      - [x] 6.4.1.2 Subtask - Confirm predecessor completion-bound artifacts and `/bh01/` remain unchanged and measurement/acceptance result sets remain empty.
      - [x] 6.4.1.3 Subtask - Record exact commands, counts, negative outcomes, environment, active browser versions, and limitations.

    - [x] 6.4.2 Task - Publish the Phase 6 decision.

      - [x] 6.4.2.3 Subtask - Leave Phase 7 eligible but unauthorized.

## Section delivery rule

Complete and verify each section before its commit. Open and merge one pull
request only after Section 6.4 passes. Phase 6 composes existing host lifecycle
boundaries and may add profile-specific fixture behavior, but it must not make
the DOM renderer, Phoenix command authority, component model, measurement
budgets, or product support part of BH-03.
