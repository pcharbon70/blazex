# BH-01 Phase 9 Measurement, Mobile Viability, and Artifact Economics Evidence

## Decision

BH-01 Phase 9 is complete with a **conditional proceed** decision for continued
framework development in the active Linux matrix. The result is not a clean
performance pass: the unpruned application AVM exceeds both application
payload budgets, the Firefox development build exceeds the local timer-event
p95 target, and representative rerun drift remains visible in Chrome startup
and server timing distributions. Each active failure has a bounded mitigation,
owner, and repeat rule; no quality threshold was changed.

All browsers remain unsupported. Mobile viability remains undecided because no
representative Android or iOS/iPadOS physical-device environment was available.
Cross-platform, mobile, Safari, second-machine, and unavailable manual evidence
is explicitly deferred to BH-22 and excluded from active pass rates. Phase 10
is eligible but not authorized.

## Governed measurements

The primary browser records contain 1,303 Chrome and 1,301 Firefox samples.
They cover cold and warm startup, fallback, local/nested/form/timer behavior,
authenticated server success and denial, reconnect/retry, memory observations,
reliability, and cleanup. Ten dependency-cached profile build samples and 69
manifest-derived artifact observations account for all 23 profile assets.

All 41 primary desktop distributions satisfy the Phase 9 harness sample
minimums. No raw sample was excluded as an outlier, every browser run retains
an empty failure list, and every primary and rerun browser record references
the same profile-manifest SHA-256
`818ac7b967db6519c766f9d1fff80455cc92d205e3f188252e6da27258ee4aad`.
Firefox cannot provide the optional JavaScript heap metric through the selected
automation interface, so that field remains unavailable rather than zero.

## Artifact economics and active budgets

The profile totals 7,827,221 decoded bytes and 2,513,184 deterministic Brotli
bytes across 23 requests. The unpruned application AVM contributes 84.045% of
decoded bytes and 87.504% of Brotli bytes. That artifact includes application,
runtime, and library modules, so the evidence does not pretend that all bytes
are user component code.

The unchanged quality contract produced 52 explicit evaluations: 23 active
passes, one early active pass, four active failures, five inactive budgets,
seventeen insufficient-boundary/sample results, one environment-not-applicable
result, and one deferred result. The four active failure rows reduce to three
owned categories: decoded application payload, compressed application payload,
and Firefox timer-event p95. Four bounded optimization candidates were
retained, four prohibited shortcuts were rejected, and no estimated saving
received budget credit.

## Reproducibility finding

The representative subset retained two 273-sample Chrome reruns and one
271-sample Firefox rerun. The first representative rerun comparison found two
Chrome startup distributions outside tolerance: fallback readiness and Wasm
instantiation readiness. A second Chrome run was collected to determine whether
that finding was a one-off; it found two different drifts in authorization
denial and disconnect/retry timing. The first report was preserved instead of
being replaced by the retry.

This representative rerun drift is a real limitation of the current
single-machine scheduler and automation baseline. It does not invalidate the
functional evidence or the deterministic derived reports, but it prevents a
strong cross-run performance-reproducibility claim and remains a Phase 10
review input.

## Deterministic integration gate

The Phase 9 verifier composes the retained Phase 8 and generated-profile gates;
validates raw browser, build, artifact, summary, deferral, economics,
mitigation, budget, stop-decision, rerun-comparison, and completion schemas;
checks reciprocal metric/budget links and immutable hashes; and regenerates all
seven derived reports twice. Each generated byte stream must match both its
second generation and the committed report. Mutation tests reject missing raw
samples, excluded outliers, hidden failures or rerun drift, threshold changes,
mobile/support promotion, open active work, and Phase 10 over-authorization.

## Limitations and next boundary

- The results describe one Linux x86-64 development host and exact qualified
  Chrome/Firefox binaries, not a browser support range.
- No second clean controlled Linux machine was available for performance
  comparison; this remains deferred alongside external platforms.
- Browser scheduling produced timing drift under the current tolerance policy.
- The build timer measures dependency-cached profile packaging rather than a
  complete cold dependency acquisition and runtime toolchain rebuild.
- Firefox automation lacks a reliable JavaScript heap observation, and browser
  parent-frame visibility into all runtime resources remains incomplete.
- Physical-device, mobile lifecycle, thermal, power, touch, virtual-keyboard,
  assistive-technology, and Safari evidence remains deferred to BH-22.
- Phase 10 may independently rebuild and reconcile this evidence only after a
  separate authorization. BH-02 and support promotion remain out of scope.
